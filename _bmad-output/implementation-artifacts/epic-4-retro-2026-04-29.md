## What Went Well

1. **Code review caught real, impactful bugs — consistently.** 20 patches across 7 stories. The nginx `add_header` inheritance bug in 4-7 meant security headers weren't actually being sent. The volume ownership issue in 4-3 would have caused runtime failures. React 19 mislabeled as React 18 in the README. The 3-layer review (Blind Hunter, Edge Case Hunter, Acceptance Auditor) earned its cost.

2. **Quality far exceeded minimum thresholds.** 98.61% client coverage, 100% server coverage — against a 70% target. Every NFR passed by a wide margin (interaction timing 16–60ms vs 300ms threshold; CLS 0.0088 vs 0.1 threshold; Lighthouse 100/100). Zero WCAG violations at Level A and Level AA. Zero dependency vulnerabilities.

3. **Mid-epic scope change was absorbed cleanly.** Went from 4 planned stories to 7 via structured sprint change proposal (Docker Compose replacing cloud deployment, plus performance/accessibility/security stories). No stories failed, no rework, no epics replanned. Foundations from Epics 1–3 were stable and untouched.

4. **Accessibility foundations from earlier epics paid compound returns.** Story 4-6 only needed one fix (the `<title>` tag). ARIA live regions, focus management, semantic HTML — all built into Epic 3 components — meant the audit was trivial rather than a painful remediation.

5. **Security controls were already solid.** Prepared statements in `TaskRepository`, error suppression in `errorHandler.ts`, CORS via `@fastify/cors`, non-root Docker users — the OWASP Top 10 review confirmed correct implementation across the board.

## What Didn't Go Well

1. **nginx configuration was a recurring source of subtle bugs.** Stories 4-3 and 4-7 both hit pitfalls: `add_header` directives silently dropped when `location` blocks define their own; `expires` creating duplicate `Cache-Control` headers; missing `server_tokens off`; `sed` pid-path patch needing verification assertions. nginx's counterintuitive inheritance model caused multiple review-only catches.

2. **Version drift between planning docs and actual dependencies.** Story 4-2 README said "React 18" and "Vite 6" but `package.json` had React 19.2.5 and Vite 8.0.10. Same root cause flagged in Epic 1 and Epic 2 retros — assumptions in docs not updated when implementation diverges.

3. **Node.js `node:test` coverage tooling is immature.** Story 4-4: `--test-coverage-include` CLI flags produced incorrect numbers when combined with `--experimental-test-module-mocks`. Workaround: programmatic `run()` API. No `--test-coverage-lines=70` threshold flag until Node.js 23+.

4. **Docker builds couldn't be verified at runtime.** Story 4-3 created Dockerfiles, Docker Compose, and healthz endpoints — but Docker daemon wasn't running. All verification was structural only. su-exec volume ownership, better-sqlite3 native compilation, multi-stage builds — correct on paper but unverified.

5. **Deferred work accumulated significantly.** 33 deferred items across 7 stories. 5 items carried forward from Epic 2 without resolution (id params accepting negative integers, missing `additionalProperties: false`, no response schemas). The `must-fix-when:` tagging action item from Epic 2 was only partially applied.

## Root Cause

Two systemic issues persisted across the project:

1. **Planning document drift** — assumptions encoded early, not validated or updated when implementation diverges. Flagged in Epic 1, Epic 2, and now Epic 4. Retrospective action items alone have not fixed this.

2. **Deferred work lacks trigger conditions** — items are logged with reasons but not with actionable conditions for when they must be addressed. This allows items to roll forward indefinitely.

## Key Insights

1. **Code review is the most effective quality gate in the process.** 20 patches across 7 stories — real bugs, not noise. The 3-layer review model justifies its cost.

2. **Baking quality in early pays compound returns later.** Accessibility is the proof: Epic 3 investment turned what could have been a painful remediation story into a trivial one-fix audit.

3. **Mid-epic scope changes are absorbable when foundations are stable.** 4→7 stories mid-flight worked because Epics 1–3 were done and untouched. Don't change scope on unstable ground.

4. **Deferred work needs trigger conditions, not just reasons.** `must-fix-when:` annotations should be applied from project kickoff, not retroactively.

5. **Planning document drift is a persistent problem that retrospectives alone don't fix.** Three retrospectives have flagged this. The process needs a structural fix — automated verification or mandatory doc-update tasks in story definitions.
