# Story 1.3: Backend Workspace Bootstrap

Status: done

## Story

As a developer,
I want a Fastify + TypeScript backend workspace with node:test available,
so that I can start the API server and run server-side tests from day one.

## Acceptance Criteria

1. **Given** `server/` is initialized via `fastify generate server --lang=ts` **When** the developer runs `npm run dev` in `server/` **Then** the Fastify server starts on port 3000 with no errors and logs in pino-pretty format
2. **Given** the auto-generated `server/test/` directory was created by fastify-cli **When** setup is complete **Then** `server/test/` has been deleted (tests are co-located per architecture conventions)
3. **Given** `server/tsconfig.json` exists **When** reviewed **Then** it extends `../tsconfig.base.json`
4. **Given** `better-sqlite3`, `@types/better-sqlite3`, `@fastify/cors`, `@fastify/sensible`, and `pino-pretty` are installed **When** `server/package.json` is reviewed **Then** all five are present as dependencies
5. **Given** `server/data/.gitkeep` exists and `server/migrations/` directory exists **When** `.gitignore` is reviewed **Then** `server/data/todo.db` is gitignored but `server/data/.gitkeep` is tracked
6. **Given** `server/.env.example` exists **When** reviewed **Then** it contains `PORT=3000`, `DATABASE_PATH=./data/todo.db`, `CORS_ORIGIN=http://localhost:5173`
7. **Given** `npm run test` is run in `server/` with no test files present **When** `node --test` executes **Then** it exits 0 (no tests is acceptable; runner is confirmed operational)

## Dev Notes

### Context from Stories 1.1 and 1.2

Story 1.1 (done) established:
- **`tsconfig.base.json`** uses `"baseUrl": "."` at monorepo root + `"@shared/*": ["shared/*"]` — the `@shared/*` path alias resolves from the monorepo root. When `server/tsconfig.json` extends `../../tsconfig.base.json`, TypeScript resolves `@shared/types` → `<monorepo-root>/shared/types.ts`.
- **ESLint v8** CJS chain: `server/.eslintrc.js` extends `../../.eslintrc.base.js`. Both files must use `module.exports` (CJS format).
- **Root `.gitignore`** already covers `*.db` (ignores `todo.db`), `.env*` with `!.env.example`, `node_modules/`, `dist/`, `build/`.
- **TypeScript 5.x** is already in root devDependencies — do NOT re-declare in `server/package.json`.

Story 1.2 (done) produced a pattern to follow:
- Fastify scaffold (like Vite scaffold) generates files that must be **modified/removed** — do not keep defaults blindly
- The most important modification is replacing the generated `tsconfig.json` to extend the base
- Verify each generated file against the architecture-specified shape before accepting it

### fastify-cli Generated Structure

Running `fastify generate server --lang=ts` from `server/` creates:

```
server/
├── package.json          ← keep; add deps in Task 3
├── tsconfig.json         ← REPLACE with base-extending config (Task 2)
├── app.ts                ← keep; the Fastify factory (autoload plugins+routes)
├── server.ts             ← keep; binds to PORT and starts app
├── plugins/
│   ├── support.ts        ← keep or simplify; this is a demonstration plugin
│   └── sensible.ts       ← keep; fastify-sensible registered here (if generated)
├── routes/
│   ├── root.ts           ← can remove the default route body; keep file as stub
│   └── ...
└── test/                 ← DELETE ENTIRELY (co-located tests only)
```

> **`@fastify/autoload`** — the generated `app.ts` uses autoload to scan `plugins/` and `routes/` directories. Do not remove this pattern; it will be used by Stories 2.x to register `db.ts`, `cors.ts`, etc.
> **`fastify-tsconfig`** — the generated tsconfig might extend `fastify-tsconfig` instead of our base. Replace the entire `extends` value with `../../tsconfig.base.json`.

### `server/tsconfig.json` — Required Shape

```json
{
  "extends": "../../tsconfig.base.json",
  "compilerOptions": {
    "outDir": "build",
    "rootDir": ".",
    "module": "CommonJS",
    "moduleResolution": "node"
  },
  "include": ["."],
  "exclude": ["node_modules", "build"]
}
```

> **Why override `module` + `moduleResolution`?** The base config uses `"module": "ESNext"` and `"moduleResolution": "bundler"` — these are correct for Vite (client-side bundler). For Node.js (Fastify), CommonJS is the runtime format and `node` is the standard resolver. Both settings are TypeScript-only; they do not affect runtime behaviour in the same way as Vite.
> **strict, target, paths, esModuleInterop** are inherited from `tsconfig.base.json` — do NOT redeclare them.
> **Do NOT add `"paths"`** — `@shared/*` alias is inherited from the base; any local override will break the resolution and cause "Cannot find module" errors.

### `server/package.json` — Dependencies Shape

```json
{
  "name": "server",
  "version": "0.0.0",
  "private": true,
  "scripts": {
    "dev": "fastify start -l info -P app.ts",
    "build": "tsc",
    "start": "node build/server.js",
    "test": "node --test",
    "test:watch": "node --test --watch",
    "lint": "eslint src --ext .ts"
  },
  "dependencies": {
    "fastify": "^5.x",
    "@fastify/autoload": "^6.x",
    "@fastify/sensible": "^6.x",
    "@fastify/cors": "^10.x",
    "better-sqlite3": "^12.9.0",
    "close-with-grace": "^2.x",
    "fastify-plugin": "^5.x",
    "pino-pretty": "^13.x"
  },
  "devDependencies": {
    "@types/better-sqlite3": "^7.x"
  }
}
```

> **`typescript` and `eslint` not redeclared** — hoisted from root devDependencies via npm workspaces. Redeclaring causes version drift.
> **`better-sqlite3@12.9.0`** — exact major version pinned as specified in architecture. Use `^12.9.0`.
> **`pino-pretty` in `dependencies`** (not `devDependencies`) — fastify-cli's `fastify start -P` flag expects pino-pretty at runtime during development; some deployment environments also use it. If explicitly not needed in prod, move to devDependencies.
> **`close-with-grace`** — generated by fastify-cli; used in `server.ts` for graceful shutdown (SIGTERM handling). Keep it.

### `server/.eslintrc.js` — Exact Content

```js
module.exports = {
  extends: ['../../.eslintrc.base.js'],
  env: {
    node: true,
    es2022: true,
  },
}
```

> **CJS format required** — both `.eslintrc.base.js` at root and this file must use `module.exports`. ESLint v8 discovers and chains CJS configs.
> **`node: true`** — defines Node.js global variables (`process`, `Buffer`, `__dirname`, etc.). The base sets useful TypeScript globals; this adds the Node runtime environment.
> **No React or browser settings** — server code has no JSX or DOM.

### `server/.env.example` — Exact Content

```
PORT=3000
DATABASE_PATH=./data/todo.db
CORS_ORIGIN=http://localhost:5173
```

> **`DATABASE_PATH=./data/todo.db`** — relative path resolved from `server/` working directory. The Fastify server reads this via `process.env.DATABASE_PATH` in Story 2.1 when the SQLite plugin is added.
> **`CORS_ORIGIN`** — consumed by `@fastify/cors` plugin in Story 2.2. Having it here from the start avoids confusion when that story runs.
> **No `VITE_API_URL`** here — that is a client-only variable in `client/.env.example`.

### Runtime Path Alias Note (`@shared/*`)

The `@shared/types` alias is NOT imported by the server in Story 1.3. It will first be used in Epic 2 (Story 2.1 — `TaskRepository.ts`). When that import is added:
- **TypeScript type-checking** resolves `@shared/*` → `<monorepo-root>/shared/*` via `tsconfig.base.json` `paths` + `baseUrl` — this works automatically.
- **Runtime resolution with `fastify start` (ts-node)** — if ts-node does not automatically register tsconfig paths, add `"require": ["tsconfig-paths/register"]` to `tsconfig.json` or install `tsconfig-paths` and configure the dev script. **This is NOT a concern for Story 1.3** — flag it in Story 2.1 when the first `@shared/types` import is added.

### `server/types/fastify.d.ts` — Placeholder Role

The module augmentation file (`FastifyInstance` decorated with `db: Database`) is created in Story 2.1 (`sqlite-schema-and-taskrepository`). The empty placeholder created in Task 9 simply ensures the `types/` directory exists and TypeScript includes it in compilation. It avoids an `include` mismatch when Story 2.1 adds the real augmentation.

### Architecture Compliance

- Test files are **co-located** with source (`foo.test.ts` next to `foo.ts`) — NOT in any separate `test/` directory
- ESLint v8 + CJS config chain must be consistent throughout
- `server/data/todo.db` is gitignored via the root `*.db` rule — verify, do not add a duplicate
- Do NOT implement any feature code (no `TaskRepository`, no routes for `/api/tasks`, no db plugin) — those belong to Epic 2

### Anti-Patterns to Avoid

| Anti-pattern | Correct approach |
|---|---|
| Keep `server/test/` directory | Delete entirely — co-located tests only |
| Re-declare `typescript` in `server/package.json` | Hoisted from root — no redeclaration |
| Add `"paths"` to `server/tsconfig.json` | Already inherited from `tsconfig.base.json` |
| Import `@shared/types` in Story 1.3 | No shared types needed yet — add in Story 2.1+ |
| `extends: "fastify-tsconfig"` | Replace with `"extends": "../../tsconfig.base.json"` |
| Keep `"module": "ESNext"` for server | Override to `"CommonJS"` in `server/tsconfig.json` |
| Use relative path `../../shared/types` | Always use `@shared/types` alias |
| Feature code (TaskRepository, routes) | Belongs to Epic 2 — scaffold only in this story |

### Completion Notes List

1. **Path depth correction**: Story dev notes said `extends: "../../tsconfig.base.json"` and `../../.eslintrc.base.js` — both wrong. `server/` is 1 level deep; correct paths are `../tsconfig.base.json` and `../.eslintrc.base.js`.
2. **`"type": "module"` required**: Added to `server/package.json`. Without it, fastify-cli uses `require()` to load `app.ts`, which returns an ESM namespace object — fastify-cli's `isInvalidAsyncPlugin` crashes on `plugin.constructor.name`. With `"type": "module"`, fastify-cli correctly uses `import()` instead.
3. **`module: "NodeNext"` not `"CommonJS"`**: When `"type": "module"` is set, TypeScript requires `module: "NodeNext"` (not `"CommonJS"`). Changed `moduleResolution` accordingly.
4. **`import.meta.dirname` not `__dirname`**: In ESM context, `__dirname` is not defined. Replaced in `app.ts` with `import.meta.dirname` (available in Node 21+).
5. **`import type` for type-only imports**: Required so Node.js native strip-types can strip them cleanly at runtime. Applied to `FastifyPluginAsync`, `FastifyServerOptions`, `FastifySensibleOptions`.
6. **`.eslintrc.cjs` not `.eslintrc.js`**: ESLint requires `.cjs` extension for CJS config files when the package declares `"type": "module"` — same pattern as `client/.eslintrc.cjs`.
7. **fastify-cli generates `server/src/` — restructured**: Files were generated under `server/src/`; moved `app.ts`, `plugins/`, `routes/` to `server/` root to match architecture spec. The `server/src/` directory was removed.
8. **`AutoloadPluginOptions` removed**: `@fastify/autoload` v6 does not export `AutoloadPluginOptions` at runtime. Removed this import from `app.ts` to prevent runtime failure.
9. **`routes/example/` deleted**: Boilerplate generated directory; removed as it is not part of the architecture.
10. **`plugins/support.ts` simplified**: Removed the boilerplate `someSupport` decorator. Kept the file as an empty `fastify-plugin` stub.
